## Current architecture and validation

- Gemini text and Live models receive only enabled, available actions without confirmation requirements: `system.get_metrics`, `memory.recall`, and read-only workspace file actions. File mutations, file undo, and `web.search` remain confirmation-gated and are not model-callable.
- Text and Live tool-call dispatch, function responses, and four-call turn limits are covered by fake-session tests; real Gemini action-call behavior remains unverified.
- Registry duplicate/timeout, parameter validation, result structure and history: backend unit tests.
- Authenticated discovery, read-only metrics/workspace execution, file mutation confirmation, path traversal rejection, network confirmation gate, invalid parameters and disable behavior: backend API tests.
- Registry-driven Actions UI and execution rendering: frontend tests.
- Computer-control AI requests only enqueue bounded, expiring proposals; API tests prove no input occurs until explicit confirmation, approval is one-shot, and the renderer can approve/reject. Stop is latched until re-armed, operation watchdog and backend-shutdown revocation are tested.
- Latest validation: backend 109 passed, 1 skipped, 3 dependency/deprecation warnings; frontend 25 tests passed across 6 files and TypeScript/Electron TypeScript/Vite production build passed. Pyperclip and PyInstaller dependencies were restored from `requirements.txt`. Guarded Windows smoke verified focus/window inspection, mouse click/type, clipboard write/paste, field clear, downward scroll by Text viewport movement, and screenshot. A separate disposable Tk target received `WM_CLOSE` and its process exit was verified. Live Gemini visual search and live proposal approval were not tested.

## Acceptance gaps

Tool-call end-to-end testing against real Gemini credentials, durable execution audit history, general undo beyond the scoped workspace, webcam capture, full action parity, platform-specific side-effect tests, and all actions marked “None” above remain incomplete. A02 still needs live Gemini proposal-to-result/visual-search verification and a fuller source-to-Alex runtime comparison before it can be accepted as complete.

## A02 computer-control scope and evidence

- **Source behavior inspected:** [`actions/computer_control.py`](../../Mark-LVI-main/actions/computer_control.py) dispatches the listed operation handlers; [`core/appidentity.py`](../../Mark-LVI-main/core/appidentity.py) identifies running processes/windows and provides target focus/close behavior. The original handler directly executes model tool calls, saves screenshots under the user's home directory, uses PyAutoGUI/Pyperclip, and uses OS-specific window mechanisms.
- **Alex safety boundary:** [`computer_control_service.py`](../backend/app/services/computer_control_service.py) validates operation-specific Pydantic inputs, display coordinates, text sizes and operation limits. [`computer_control.py`](../backend/app/actions/builtins/computer_control.py) registers separate proposal/status/approval/stop actions. Permission is off by default and session-only; proposals are immutable server-side parameters, expire after five minutes, and are limited to five pending requests. Only the renderer can reach the confirmation-gated approval endpoint through the explicit bridge. Approval consumes the ID before execution; rejected, expired, modified, replayed and unauthorized operations do not run. Stop clears proposals, latches until permission is re-armed, and is checked at safe checkpoints; the 12-second watchdog and backend-shutdown revocation remain enabled.
