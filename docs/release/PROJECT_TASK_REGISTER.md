## 1. Overview and Taxonomy

This register provides the consolidated, single source of truth for all engineering, architectural, documentation, and validation tasks across the Alex project. It strictly separates **Implementation Status**, **Automated Test Status**, and **Physical Runtime Acceptance Status**.

### Priority Classifications
- **P0 (Critical):** Core workflow broken, or high-impact safety, security, or data-loss requirement. Must precede any deployment or broader feature work.
- **P1 (High):** Major functional requirement, core user workflow, or high-risk parity gap.
- **P2 (Medium):** Supporting feature, provider integration, secondary workflow, or non-critical enhancement.
- **P3 (Low):** UI polish, optional enhancement, or non-essential cosmetic improvement.

### Implementation Statuses
- **Completed:** Fully implemented in source code.
- **Completed (FROZEN):** Fully implemented, verified via automated tests, and placed under strict implementation freeze by governance mandate.
- **In Progress:** Functional implementation exists, but parity, edge cases, or packaging remain in development.
- **Pending:** Not yet implemented in the Alex codebase.

### Automated Test Statuses
- **Verified (Pass):** Unit, service, API, or component test suites execute and pass deterministically in automated harnesses.
- **Partial:** Automated tests exist for a subset of behaviors; edge cases or negative tests remain unwritten.
- **Untested:** No automated test suite currently covers this capability.
- **N/A (Document):** Architectural or documentation artifact; verified by review.

### Runtime Acceptance Statuses
- **Accepted:** Formally verified through end-to-end physical runtime execution on target hardware with live credentials and verified evidence logs.
- **Not Accepted:** Implementation complete and unit tests pass, but formal runtime verification criteria are incomplete or audit conditions remain unfulfilled.
- **Blocked by Environment:** Execution cannot be validated on the current host due to environmental security policies (e.g., Active Directory SRP/AppLocker blocking PowerShell) or absent physical hardware peripherals (microphone, physical display, speakers).
- **Pending Validation:** Code is automated-test verified, but awaiting formal end-to-end runtime validation by an authorized tester on an unrestricted workstation.
- **Untested:** Implementation not yet evaluated against runtime acceptance criteria.
